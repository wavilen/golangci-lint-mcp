# G118

<instructions>
Detects context propagation failures: uncalled cancel functions, goroutines using `context.Background()` when a request context is available, and blocking I/O loops that ignore `ctx.Done()`. These patterns leak goroutines and resources because cancellation signals never reach downstream work. Always `defer cancel()` for derived contexts, propagate request contexts into goroutines, and select on `ctx.Done()` in long-running loops.
</instructions>

<examples>
## Good
```go
func handler(w http.ResponseWriter, r *http.Request) {
    ctx, cancel := context.WithTimeout(r.Context(), 5*time.Second)
    defer cancel()
    go doWork(ctx) // propagate request context
}
```
</examples>

<patterns>
- Ensure the cancel function from `context.WithTimeout`/`WithCancel` is stored and `defer cancel()` is called immediately
- Pass the request context to goroutines instead of `context.Background()` — use `r.Context()`
- Check `ctx.Done()` in long-running loops — select on `ctx.Done()` alongside blocking operations
</patterns>
